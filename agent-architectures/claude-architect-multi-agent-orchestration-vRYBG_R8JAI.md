## TubeOnAI Summary
> 🔥 Hub-and-spoke coordinator pattern  
  – A single Coordinator sits at the center handling task decomposition, routing, context sharing, aggregation, and error handling; spokes/sub-agents never communicate directly.  
  – Benefits include centralized observability, controlled context flow, and a single choke point for telemetry and safeguards.

🧭 Coordinator responsibilities and routing logic  
  – Break tasks into subtasks, decide which agents to call and in what order (sequential/parallel), and merge results into a coherent output.  
  – Use dynamic routing: only invoke agents that answer real questions; skip steps for simple factual cases; adapt paths for non-traditional or complex profiles.

🧩 Concrete use case: job application screening  
  – Spokes include a Keyword Scanner, Deep Evaluator, and Red-Flag Detector, with the coordinator orchestrating and aggregating.  
  – Later shifted to a single “screening agent” specialized via screening angles generated by the coordinator to widen coverage.

⚠️ Pitfall: narrow task decomposition  
  – Overly narrow subtasks miss critical dimensions (e.g., policy, infra, supply chain in market research; depth, impact, and scale in hiring).  
  – Add pre-delegation checks and an aggregation-level coverage checklist, and instruct the coordinator to explicitly ask “what’s missing” before delegating.

🔀 Dynamic selection (adaptive pipelines)  
  – Don’t run the full pipeline each time; selectively invoke agents based on the brief and observed evidence.  
  – Encode routing guidance (e.g., skip keyword scan if evidence is conclusive; add transfer-skill checks for non-traditional backgrounds).

🧱 Partitioned research to avoid overlap  
  – Generate a JSON of non-overlapping partitions with fields like agent, scope, cover, and exclude; each partition owns a distinct slice.  
  – Coordinator delegates exactly one call per partition; move routing criteria into the partition planner to decide which partitions exist.

🔁 Refinement loop for iterative quality  
  – Introduce up to 3–4 refinement iterations: evaluate coverage, identify gaps, invoke agents only for missing angles, then re-evaluate.  
  – Submit final only when coverage is sufficient and conflicts resolved.

🕵️ Observability and safeguards  
  – Add structured logging (timestamp, levels), error handling around JSON/parsing, mid-run coverage evaluation gates, and persistent audit trails of inputs/outputs.  
  – Enforce context control by scoping questions to partition rules; enable spoke isolation and reject out-of-scope prompts.  
  – Track token counts, latency, request IDs, and produce replayable logs and human-readable reports.

🧱 Refactoring for maintainability  
  – Split code into prompts/ (Markdown prompts), tools/ (tool functions), lib/ (partitions, coordinator, logger, templates), data/ (inputs), and reports/ (outputs).  
  – Convert core flows into a stateless class with small, named functions; load prompts via templates; generate timestamped coverage reports.  

🧰 Port to Claude Agent SDK  
  – Replace raw Anthropic SDK usage with Claude Agent SDK; define tools using the @tool decorator and run an internal MCP server for tool invocation.  
  – Adjust message calls accordingly and factor tools into separate files with factories to capture coordinator state.

🧪 Implementation cautions  
  – Add a max-steps cap for loops, prefer JSON-structured logs for downstream parsing, and modularize state for testability.  
  – Consider per-tool model selection and clear separation of concerns to ease evaluation and future changes.
